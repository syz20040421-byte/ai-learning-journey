# 学习笔记
1. `BaseModel：类声明 = 校验规则`：pydantic库的基类，主要用作数据校验（是否符合字段设定的类型注解）和格式转换（将实例转换为dict或者json（.dict(),.json()）。
- 用法：
  ```python
  class Student(BaseModel):
    name: str
    age: int
  s = Student(name="张三", age=20)   # 如果传入时age="20"，会自动将20从字符串转为int
  Student(name=123, age=20)          # name 不是 str → 抛 ValidationError
  ```
2. Field约束：约束直接写在字段声明处：`score: float = Field(ge=0, le=100)`
- 参数如下：
    （1）default / default_factory：设置默认值或动态生成默认值的函数。
    （2）alias：为字段设置别名，在验证和序列化时都会生效。
    （3）title / description：为字段添加标题和描述，主要用于生成文档。
    （4）gt / ge / lt / le：用于数字字段，分别表示大于、大于等于、小于、小于等于。
    （5）min_length / max_length：用于字符串或列表字段，限制其长度。
    （6）pattern：用于字符串字段，要求其匹配指定的正则表达式。
    （7）exclude：在导出模型时（如.dict()或.json()）排除该字段。

3. ValidationError 结构：本质是一个报错信息库，用`try...except ValidationError as e:`捕获后，调用e.errors()可获取存储错误信息的列表，列表由字典组成，每一个字典就是一个字段的报错信息，有关参数如下：
（1）type：（错误类型）错误的类型标识符（如string_too_short，greater_than），机器可读，便于程序逻辑判断。
（2）loc：（错误字段及位置）错误发生的位置，是一个元组，第一个元素就是错误字段。最常用的是('field_name',)。对于嵌套模型或列表，它会显示完整的路径，如('items', 0, 'price')表示列表的第一个元素的price字段出错。
（3）msg：（人类可读的错误信息）人类可读的错误描述，用于直接展示给开发者或用户。
（4）input：导致错误的原始输入值，方便调试。
（5）ctx：一个字典，提供错误的额外上下文，例如{'min_length': 1}表示长度必须大于等于1。
（6）url：指向官方文档该错误类型说明的链接。
- 用法：
  ```python
  except ValidationError as e:
      first = e.errors()[0]
      print(first["loc"], first["msg"])   # ('age',)  Input should be a valid integer
  ```
4. 嵌套模型 + List[Model]：一个类的实例属性可以是另外一个类或者类的列表，如：`class ClassRoom(BaseModel): students: list[Student]`

5. 卡点：在`safe_score()`函数中，我原本`try:stu1 = Student(name=row["name"],age=row["age"],score=row["score"])`直接就赋值了，若 row 缺少 "name" 等字段，会抛出 KeyError，而不是 ValidationError，导致异常未被捕获，函数崩溃，后面查资料改成了现在的样子，直接解包赋值，让 Pydantic 校验所有字段。

- FastAPI的请求体校验属于整体校验（一条坏全部拒收），当数据中存在坏数据时FastAPI会直接报错
