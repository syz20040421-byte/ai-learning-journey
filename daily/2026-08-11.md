## 今日知识点预习 (10-15 min)

0. **运行环境（昨天最可能的卡点，先看这个）**：你的 `python` 命令指向 hermes 环境（没有 requests），必须用仓库的 `.venv`。两种跑法任选：
   - `source .venv/Scripts/activate` 激活后再 `python 06_integration.py`
   - 或直接 `.venv/Scripts/python.exe 06_integration.py`
   - 已实测：`.venv` 里 requests 2.33.0，open-meteo 返回 200
1. **requests 库**：`requests.get(url, params=..., timeout=10)` 发 GET；`.status_code` 是状态码（200=成功）；`.json()` 把响应解析成 dict/list
2. **URL 查询参数**：`?latitude=39.9&longitude=116.4` 是问号后的键值对，API 靠它收参数
3. **timeout 为什么必须设**：网络请求可能永远不返回（断网/服务器挂），不设 timeout 程序无限卡住；文件读取出错立刻抛异常，网络请求失败可能「沉默地等」——这是文件 IO 和网络 IO 最大的区别（今日一问也考这个）
4. **嵌套 dict 访问**：`d["current_weather"]["temperature"]` 一层层取；先 `in` 或 `.get()` 确认 key 存在，不然 KeyError
5. **坏数据处理**（复习 Day 4/5）：逐行 try/except，坏行打印原因跳过，绝不整脚本崩
6. **单点失败隔离**：每个城市一个 try/except，一个失败不影响其他城市

### 3. 编码 (180-240 min · 主体) — `submissions/2026-08-10/06_integration.py`

把昨天的 pass 桩全部实现，按顺序做：

**① 造数据 `cities.csv`**（放 `submissions/2026-08-10/`，含表头 `city,latitude,longitude`）：

```

北京,39.9042,116.4074

```

最后一行是**坏数据**，验证脚本能跳过不崩。

**② 实现三个函数**（签名不许改）：

- `load_cities(path: str) -> list[dict]`：逐行读 CSV，坏行打印原因跳过（复用 Day 5 逐行模式）；文件不存在打印提示、返回空列表
- `fetch_weather(lat: float, lon: float) -> dict | None`：GET `https://api.open-meteo.com/v1/forecast?latitude={lat}&longitude={lon}&current_weather=true`，**timeout=10 必须设**；成功返回 `{"temperature": ..., "weathercode": ...}`；失败（超时/断网/状态码非 200）打印错误、返回 None，**不抛异常**
- `save_results(rows: list[dict], path: str) -> None`：把 `[{"city":..., "temperature":..., "weathercode":...}]` 写进 `weather.csv`（表头 `city,temperature,weathercode`，encoding="utf-8"）

**③ 主流程**（文件末尾）：读 cities.csv → 对每个城市 fetch_weather → 跳过返回 None 的城市 → 打印每个城市 `城市 温度` → save_results 写 weather.csv

**④ 写完必须真跑，逐条自测**：
- 北京/上海/广州三行都出现在 weather.csv，温度与打印一致
- 月球那行被跳过且打印了跳过原因，脚本不崩
- 每个请求都设了 timeout；单城市失败不影响其他城市
- 全程自己 debug：可以问 AI「为什么报这个错」，**禁止让 AI 写完整代码**（AI 代写 = 第 8 周手写 agent 时崩）
