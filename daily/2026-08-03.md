## 任务清单

### 1. GitHub 环境搭建（45–75 min，先完成）

这是环境配置，不是能力测试：**这一项允许查官方资料和问 AI**。但不要把 PAT、Webhook、任何密钥发给任何人，包括我。

1. 在 Git Bash 执行以下命令，把邮箱替换成**已验证且与 GitHub 账号一致**的邮箱；不一致，贡献图不会正确关联。
   ```bash
   git config --global user.name "你的 GitHub 用户名或真实姓名"
   git config --global user.email "你的 GitHub 已验证邮箱"
   git config --global --get user.name
   git config --global --get user.email
   ```
2. 没有 GitHub 账号就到 <https://github.com/signup> 注册并验证邮箱；已有账号直接继续。浏览器中创建一个**公开（Public）**、空的仓库，名称必须为 `ai-learning-journey`。创建时不要勾选 README、`.gitignore` 或 license（本地已有文件）。
3. 在 GitHub 的 **Settings → Developer settings → Personal access tokens** 创建一个仅用于此仓库的 token。优先使用 fine-grained token：Repository access 只选 `ai-learning-journey`，Repository permissions 的 **Contents** 设为 Read and write；设一个短到合理的过期时间。复制后只保存在密码管理器，GitHub 不会再次显示它。
4. 在本仓库 Git Bash 执行（把 `YOUR_NAME` 改为 GitHub 用户名；不要把 token 写进命令、文件、笔记或截图）：
   ```bash
   cd "D:/work-coding/Knowledge base/AI_KnowledgeBase"
   git status
   git add .gitignore ROADMAP.md progress.json scripts daily
   git commit -m "chore: initialize AI learning journey"
   git branch -M main
   git remote add origin https://github.com/YOUR_NAME/ai-learning-journey.git
   git remote -v
   ```
   如果 `git commit` 提示没有可提交内容，先执行 `git status --short`，只暂存上述学习文件；不要用不加选择的 `git add .`。
5. **推送前安全自查**。以下命令必须没有输出；有输出就停止，先移除泄露的文件和 Git 历史，不要 push：
   ```bash
   git log --all --full-history -- scripts/.feishu_webhook
   ```
   然后推送。Git 提示输入密码时，密码位置粘贴 **PAT**，不是 GitHub 登录密码：
   ```bash
   git push -u origin main
   ```
6. 摸底完成后，再单独做第二个 commit（一次 commit 只做一件事）：
   ```bash
   git add submissions/2026-08-03 notes/2026-08-03-baseline.md
   git commit -m "test: submit Python baseline assessment"
   git push
   git log --oneline -2
   ```
   在 `notes/2026-08-03-git-setup.md` 只记录：GitHub 用户名、仓库 URL、两条 commit hash、`git remote -v` 输出。**不要记录 token。**

> 面试会看 GitHub 提交是否连续、是否能读懂提交边界；今天两次 commit 是从第一天开始建立证据，不是形式主义。

#### A. Python 语法与函数 / 作用域

1. **代码** `01_syntax.py`：实现 `fizzbuzz(n: int) -> list[str]`。返回从 1 到 n（含）的列表：3 的倍数为 `"Fizz"`，5 的倍数为 `"Buzz"`，同时为 3、5 倍数为 `"FizzBuzz"`，其他为数字的字符串。`n <= 0` 返回空列表。文件末尾至少用 3 个 `assert` 覆盖 1、15、0。
2. **文字** 在 `answers.md` 回答：Python 函数里，局部变量和全局变量的查找顺序是什么？为什么下面函数连续调用两次会得到意外结果？不要运行，写出两次返回值和原因。
   ```python
   def add_item(item, bucket=[]):
       bucket.append(item)
       return bucket
   ```

#### B. 数据结构与复杂度

3. **代码** `02_data_structures.py`：实现 `first_unique(items: list[str]) -> str | None`，返回列表中第一个只出现一次的字符串；没有则返回 `None`。不得修改 `items`。给出 `[]`、`["a", "b", "a"]`、`["x", "x"]` 的断言。
4. **文字** 在 `answers.md` 回答：要反复判断一个用户名是否已经存在，为什么通常选 `set` 或 `dict` 而不是 `list`？分别写出三者“按值/键查找”的平均时间复杂度，并说明何时仍会选 `list`。

#### C. OOP

5. **代码** `03_oop.py`：定义 `BankAccount`。构造函数接收 `owner: str` 与 `balance: float = 0`；`deposit(amount)` 只接受大于 0 的金额并返回新余额；`withdraw(amount)` 在金额不合法或余额不足时抛出 `ValueError`，成功时返回新余额。创建一个实例并覆盖成功存款、成功取款、余额不足三种情况。
6. **文字** 在 `answers.md` 回答：实例属性与类属性分别存在哪里、适合存什么？如果所有 `BankAccount` 共享一个可变的交易列表，会有什么问题？

#### D. 异常与文件 IO

7. **代码** `04_file_io.py`：实现 `load_scores(path: str) -> dict[str, int]`。文件每个非空行格式为 `姓名,分数`；忽略空行；遇到没有逗号、分数不是整数的行时跳过并打印一条包含行号的提示；文件不存在时不要让 traceback 冒到最外层，打印清晰提示并返回 `{}`。在同目录写一个 `scores.txt`，含至少 4 行有效数据、1 个空行、2 行坏数据，运行脚本。
8. **文字** 在 `answers.md` 回答：`try`、`except`、`else`、`finally` 各自何时执行？为什么不能用 `except Exception: pass` 把所有错误吞掉？

#### E. 命令行与 Git

9. **代码** `05_cli.py`：使用标准库 `argparse` 写 CLI：`python 05_cli.py --name Ada --times 3` 打印三行 `Hello, Ada`。`--name` 必填，`--times` 默认 1；`times <= 0` 时给出清晰错误并以非零状态退出。不要手动解析 `sys.argv`。

#### F. HTTP 与 SQL

11. **代码** `06_http.py`：不发真实网络请求。实现 `describe_response(status_code: int) -> str`：200–299 返回 `"success"`，400–499 返回 `"client_error"`，500–599 返回 `"server_error"`，其他返回 `"unknown"`。用断言覆盖 200、201、404、500、999。文件顶部用注释写出 HTTP 请求至少包含的两部分、响应至少包含的两部分。
12. **文字** 在 `answers.md` 写 SQL（不用安装数据库）：表 `orders(id, user_id, amount, status)`，写一条查询，找出 `status = 'paid'` 的订单中每个 `user_id` 的订单数和金额总和，只保留金额总和大于 100 的用户，按金额总和降序。再解释 `WHERE` 与 `HAVING` 的区别。
