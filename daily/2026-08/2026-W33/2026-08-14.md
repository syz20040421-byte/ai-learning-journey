### 1. 列表推导式：把循环压缩成一行

- **是什么**：`[表达式 for 变量 in 可迭代对象 if 条件]`——用一个表达式生成整个列表，代替「先 `[]` 再 append」的三行套路。
- **为什么今天用**：你前 8 天写了至少 10 处 `xx_list = []` + `for` + `append`（load_cities、records_to_dict……）。推导式是 Python 里最常用的「省三行」手法，也是面试开场白必问题。第 2 周从它开始。
- **怎么用**（注意：只是示范，不是任务答案）：
  ```python
  # 老写法
  result = []
  for x in range(10):
      if x % 2 == 1:
          result.append(x * 10)
  # 推导式
  result = [x * 10 for x in range(10) if x % 2 == 1]
  ```
- **坑**：可读性优先。推导式里套两个 for 加一个 if 还能看懂，套三个 for 就是给别人留地雷。任务里的每个推导式只允许一个 for + 一个 if。

### 2. 字典推导式 & 集合推导式：同一套路，两种容器

- **是什么**：`{k: v for ...}` 生成 dict，`{x for ...}` 生成 set，语法和列表推导式只差括号。
- **为什么今天用**：字典推导式是「反转映射」（值 → 键）、「统计」类问题的标准答案；集合推导式天然去重。第 3 周处理真实数据时全是这种结构。
- **怎么用**：
  ```python
  # 反转映射：{"a": 1} → {1: "a"}
  rev = {v: k for k, v in {"a": 1, "b": 2}.items()}
  # 集合推导式：收集所有出现过的首字母
  firsts = {word[0] for word in ["apple", "banana", "avocado"]}  # {'a', 'b'}
  ```
- **坑**：集合和字典推导式都**无序**——别期待 `{"a","b","c"}` 按你写的顺序存。另外字典的键必须可哈希（list 不行，tuple 行——Day 3 的坑今天再次出现）。

### 3. 生成器：列表的「省钱版」

- **是什么**：`(x for x in ...)` 或函数里用 `yield`。它不一次性算出所有元素，而是**要一个给一个**（惰性求值），所以占内存几乎为零。
- **为什么今天用**：这是今天预习里最重要的概念，也是面试高频题「列表推导式和生成器的区别」。你会亲手对比：列表存 10 万个数的内存 vs 生成器。
- **怎么用**：
  ```python
  gen = (x * x for x in range(1000000))   # 生成器：几乎不占内存
  lst = [x * x for x in range(1000000)]   # 列表：约 36MB
  print(next(gen))  # 要一个给一个：0
  ```
  生成器函数：函数体里出现 `yield` 就是生成器函数，调用它**不执行函数体**，返回一个生成器对象；每 `next()` 一次，执行到下一个 `yield` 停下来。
- **坑**：生成器只能从头到尾走一遍——`list(gen)` 一次后它就空了，再 `list(gen)` 是 `[]`；也没有 `len()`、不能按下标取 `gen[0]`。**能重复遍历、要长度、要下标时，必须用列表**。这是三问第 2 题的答案线索，别漏。

### 4. pathlib：让脚本任何目录都能跑

- **是什么**：`pathlib.Path` 是 Python 3.4+ 的官方路径工具，用 `/` 拼路径、`.parent` 找上级、`Path(__file__).resolve()` 定位脚本自己的绝对路径。
- **为什么今天用**：你的 `06_integration.py` 里写死了 `"submissions/2026-08-10/cities.csv"`——8/13 归档把目录挪到了 `submissions/2026-08/2026-W33/2026-08-10/`，脚本从仓库根目录跑就 FileNotFoundError 崩了（教练今天复跑已确认）。**硬编码相对路径 = 换个目录就炸**。修法：用 `Path(__file__).parent` 拿到脚本所在目录，再拼文件名，这样脚本挪到哪都能跑。
- **怎么用**：
  ```python
  from pathlib import Path
  BASE = Path(__file__).resolve().parent   # 脚本所在目录的绝对路径
  data_file = BASE / "cities.csv"          # 拼出数据文件路径
  ```
- **坑**：`Path(__file__)` 可能是相对路径（取决于你怎么运行），所以先 `.resolve()`；拼路径用 `/` 不是字符串 `+`；路径对象传给 `open()` 直接用，不用转字符串。

### 5. Git 分支：平行宇宙的代码

- **是什么**：`git branch` 从当前提交拉出一条平行线，两条线各自往前走互不干扰；`git merge` 把另一条线的改动并回来；两边改了同一处就是**冲突**。
- **为什么今天用**：第 2 周主线之一是 Git 进阶。分支是团队协作的命根子（你以后上班 90% 时间都在分支上干活），冲突处理是面试和工作的必考。今天用最简单的方式先走一遍流程。
- **怎么用**（今天练习的标准流程）：
  ```bash
  git branch feature/w1-fix        # 建分支（从当前位置分叉）
  git checkout feature/w1-fix      # 切过去
  # ...在分支上改文件、commit...
  git checkout main                # 切回主分支
  git merge feature/w1-fix         # 把分支改动并回 main
  ```
- **坑**：**不 commit 就切分支，改动会「随身携带」**（工作区是共享的），新手最容易在这困惑；冲突不是错误，是 git 在问「你俩改同一行了，留谁的？」——`<<<<<<<` 到 `=======` 是你这边的，`=======` 到 `>>>>>>>` 是对方的，手动改成想要的样子再 `git add` + `commit` 即可。

**The Foundation**

Leo wanted to build houses. On his first morning, his boss Tom handed him a shovel. "The field behind the yard," Tom said. "Dig a trench. Three meters long, one meter deep."

Leo dug. The sun was hot. His hands hurt. At the end of the day, he had a hole in the ground and nothing to show for it.

The next day: "Deeper." The day after: "Wider." For two weeks, Leo dug trenches. He did not build anything. He did not even touch a brick.

"I came here to build houses," he told Tom. "My friend Sam started the same week, and he has already built a wall. I have only dirt on my shoes."

Tom did not answer. He walked to the corner of the yard and pointed at an old house. It was small and ugly, but it had stood there for fifty years.

"In the flood of 1985," Tom said, "every new house in this village fell. Not this one. Why? Because the man who built it spent his first month digging. The flood was strong, but the foundation was stronger."

Leo looked at his trench. It was straight. The bottom was flat. He had not been wasting time — he had been building the part that no one sees.

"I will show you something," Tom said. "The houses people admire are the ones with tall walls and pretty roofs. But a house is only as good as what is under it. A strong foundation is quiet. It does not show off. It simply holds everything up — for years, for decades, for a lifetime."

After that, Leo dug with a different heart. He checked his lines twice. He made the bottom flat. He did not hurry.

Three years later, Leo built his first house. Visitors walked around it and said, "The walls are straight, the roof is lovely." Leo smiled and said nothing. At night, he stood on the hill behind the house and looked down. He could not see the foundation. But he knew it was there, deep and strong, holding everything up.

"Everyone sees the walls," he told his own student years later. "Only the builder knows the foundation. Do the quiet work first. The loud work will take care of itself."
