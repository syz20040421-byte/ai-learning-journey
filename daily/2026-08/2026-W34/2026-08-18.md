## 今日知识点预习 (15-20 min · 详读)

四段式：是什么 / 为什么今天用 / 怎么用 / 坑。

### 1. 阻塞与事件循环：为什么需要 async

- **是什么**：程序等网络请求、文件、定时器时 CPU 在空转。同步写法是「一个人排队办事」，async 是「一个人同时盯着好几件事，谁先好先处理谁」。
- **为什么今天用**：AI 应用全是网络 IO——调 LLM API、请求数据库、抓网页。第 4 周聊天工具要流式吐字，第 7 周要同时请求几十条。今天不把「事件循环」模型装进脑子，到那时只能抄框架。
- **怎么用**（看模型，不写代码）：
  ```
  同步：A 等 1s → B 等 1s → C 等 1s，总 3s（人等事）
  async：A、B、C 同时开始，谁先好先继续，总 ~1s（事等人）
  ```
- **坑**：async 不是多线程——单线程里靠「让出（await）」切换，没有 await 挂起点就没有切换。别拿「线程」的直觉理解它。

### 2. async def 与协程对象：不 await 不执行

- **是什么**：`async def` 定义的函数叫协程函数，**调用它不执行函数体**，只返回一个 coroutine 对象。
- **为什么今天用**：这是 async 最容易翻车的地方——忘了 await，函数静默不跑，还报 `RuntimeWarning: coroutine was never awaited`。
- **怎么用**：
  ```python
  async def hello():
      return "hi"

  c = hello()          # 没执行！c 是 coroutine 对象
  print(c)             # <coroutine object hello at ...>
  ```
- **坑**：coroutine 对象不是结果值，直接拿它当返回值用会出错；必须 `await c` 或在事件循环里跑才有结果。

### 3. await 与 asyncio.sleep：让出控制权

- **是什么**：`await` 是「挂起当前协程，把控制权交回事件循环，等结果好了再回来」。`asyncio.sleep(n)` 是「假装等 n 秒」——等的时候别人能插进来跑。
- **为什么今天用**：今天编码任务要靠 sleep 模拟「网络请求耗时」，靠它观察事件循环怎么切换。
- **怎么用**：
  ```python
  await asyncio.sleep(1)   # 让出 1 秒，期间其他协程可以跑
  ```
- **坑**：**`time.sleep(1)` 是真睡觉，会把整个事件循环堵死**——别的协程全卡住。异步代码里模拟耗时一律用 `asyncio.sleep`。

### 4. asyncio.gather：并发 + 保序

- **是什么**：`await asyncio.gather(a(), b(), c())` 同时启动多个协程，全部完成后一次性返回结果列表，**顺序和传入顺序一致**。
- **为什么今天用**：并发是 async 的核心价值。今天用 3 个 sleep 任务实测「并发 vs 串行」的时间差。
- **怎么用**：
  ```python
  results = await asyncio.gather(fetch("A"), fetch("B"), fetch("C"))
  # results = ["A 完成", "B 完成", "C 完成"]，总耗时 ≈ 单个任务耗时
  ```
- **坑**：`for x in xs: await f(x)` 是串行——等完一个才启动下一个。想并发必须 gather。gather 里一个协程抛异常，默认整个 gather 一起炸（今天不处理，知道有 `return_exceptions=True` 这个开关即可）。

### 5. asyncio.run：同步↔异步的桥

- **是什么**：`asyncio.run(main())` 创建事件循环、跑协程、跑完关循环。Python 3.7+ 的统一入口。
- **为什么今天用**：你的脚本是普通同步代码（`if __name__ == "__main__"`），想在里面跑协程必须通过它。
- **怎么用**：
  ```python
  asyncio.run(fetch("A", 0.1))   # 同步代码里调协程的正规方式
  ```
- **坑**：同步函数里直接 `await x` 是语法错误（`'await' outside async function`）；`asyncio.run` 不能嵌套调用（事件循环里再 run 会报错）。

### 2. 编码 (180-240 min)

**`submissions/2026-08/2026-W34/2026-08-18/async_practice.py`**（脚手架已给，填实现）：

5 个实现（每个的要求内联在文件对应位置，编号与下面一致）：

1. `async def fetch_one(name: str, delay: float = 0.05) -> str`：`await asyncio.sleep(delay)` 模拟一次网络请求，返回 `f"{name} 完成"`
2. `async def fetch_all(names: list) -> list`：对每个名字用 `asyncio.gather` **并发**发起 fetch_one，返回结果列表，**顺序与 names 一致**（gather 保序，不用自己排）
3. `async def tick_tock() -> list`：定义内部 `worker(name)` 协程循环 3 次，每次往共享 `events` 列表 append `f"{name}{i}"` 后 `await asyncio.sleep(0)` 让出；用 gather 同时跑两个 worker，返回 events——**预期 A/B 严格交替**（`["A1","B1","A2","B2","A3","B3"]`）
4. `async def compare_times(names: list) -> dict`：用 `time.perf_counter` 分别测「串行逐个 await」和「gather 并发」各跑一遍 3 个 `fetch_one(n, 0.15)` 的总耗时，返回 `{"sequential": 串行耗时, "concurrent": 并发耗时}`（浮点秒）
5. `def call_async_from_sync() -> str`：**普通同步函数**（没有 async 前缀）里用 `asyncio.run(fetch_one("桥", 0.01))` 调协程并返回结果

**自测要求**（写在 `if __name__ == "__main__":` 里，最后打印 `Day 12 全过`）：

- `fetch_one("测试", 0.01)` 不 await 时是 coroutine 对象（`asyncio.iscoroutine(...)` 为 True）——证明「不 await 不执行」

- `fetch_all(["A", "B", "C"])` 结果保序 `["A 完成", "B 完成", "C 完成"]`
- `tick_tock()` 返回 6 个事件且 A/B **严格交替**（不是 A 跑完再 B）
- `compare_times(["A","B","C"])`：`concurrent < sequential`（串行 ≈0.45s vs 并发 ≈0.15s，用 0.15 的 delay 拉开差距）
- `call_async_from_sync() == "桥 完成"`

> 面试怎么考：「async def 函数调用返回什么」→ coroutine 对象，不 await 不执行；「怎么并发跑多个任务」→ `asyncio.gather`；「`asyncio.sleep` 和 `time.sleep` 区别」→ 前者让出事件循环，后者阻塞整个循环；「async 能加速 CPU 密集计算吗」→ 不能，它只解决 IO 等待。这四句就是今天预习 1/3/4/5 的浓缩。
