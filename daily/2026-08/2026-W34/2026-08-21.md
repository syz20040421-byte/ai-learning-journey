## 今日知识点预习 (15-20 min · 详读)

### 1. HTTP 请求/响应长什么样

- **是什么**：一次 HTTP 交互 = 客户端发**请求** + 服务器回**响应**。请求 = 方法 + URL + 请求头（Headers）+ 请求体（Body，GET 通常没有）；响应 = 状态码 + 响应头 + 响应体（Body 通常是 JSON）。
- **为什么今天用**：FastAPI 的每个路由就是在定义「什么样的请求进来、返回什么响应」。今天 http_probe.py 会用 httpx 把真实响应拆开看每一块。
- **怎么用**（响应体在 Python 里的样子；网络请求统一用 **httpx**——pyproject 已声明，API 和 requests 几乎一样，第 4 周调 LLM API 也用它）：
  ```python
  resp = httpx.get("https://httpbingo.org/get?name=alice", timeout=10)
  resp.status_code   # 200
  resp.headers       # 响应头（Content-Type、Server 等）
  resp.json()        # 响应体解析成 dict（"args": {"name": ["alice"]}）
  ```
- **坑**：`resp.json()` 只有 Content-Type 是 JSON 时才有意义；`headers` 是大小写不敏感的字典。httpbingo 的 args 值是**数组**（`["alice"]` 不是 `"alice"`），取字段要带 `[0]`。

### 2. 状态码：服务器在说人话

- **是什么**：三位数字，第一位是类别。**2xx** 成功（200 OK / 201 已创建）、**3xx** 重定向、**4xx** 客户端错了（400 请求格式错 / 404 找不到 / 422 数据校验不过）、**5xx** 服务器自己崩了（500 内部错误 / 503 服务不可用）。
- **为什么今天用**：你调任何 API（包括第 4 周的 LLM）第一件事就是看状态码——2xx 才往下走，4xx 说明你传错了，5xx 说明对方挂了，处理方式完全不同。
- **怎么用**：成功判断用 `resp.is_success`——**httpx 没有 requests 的 `resp.ok` 属性**，`is_success` 只有 2xx 才为 True。注意 **httpx 默认 4xx/5xx 不抛异常**，要抛得手动 `raise_for_status()`——Day 8 你重写过 fetch_weather 就是这个原因。今天代码里怎么表达状态码：创建成功在装饰器上写 `@app.post("/students", status_code=201)`；找不到资源用 `raise HTTPException(status_code=404, detail="not found")`，响应体自动变成 `{"detail": "not found"}`（HTTPException 从 fastapi 导入）。
- **坑**：422 是「数据格式对但内容不合法」（age 传了字符串），400 是「请求本身格式就错了」——FastAPI 用 422 表示 Pydantic 校验失败，这是它的约定，面试会问。

### 3. FastAPI 和 uvicorn：谁是谁

- **是什么**：**FastAPI** 是框架——你写路由（URL 和函数的对应关系）、写校验规则，它负责把请求路由到函数、把函数返回值变成 HTTP 响应；**uvicorn** 是服务器——真正监听端口、接收网络请求的程序（FastAPI 自己不监听端口）。
- **为什么今天用**：第 3 周所有任务都跑在 FastAPI + uvicorn 上。理解「框架 vs 服务器」的分工，后面部署上线（Railway/Render）时才知道部署的是什么。
- **怎么用**：
  ```bash
  ".venv/Scripts/python.exe" -m uvicorn fastapi_first:app --reload
  # fastapi_first 是文件名，app 是文件里的 FastAPI 实例名
  ```
- **坑**：`uvicorn` 后面是 `文件名:变量名`，不是路径；`--reload` 是开发模式（改代码自动重启），部署时去掉。

### 4. FastAPI 的请求体校验 = Day 14 的 Pydantic 在干活

- **是什么**：POST 路由的函数参数写 `student: Student`（Student 是 Pydantic 模型），FastAPI 会自动把请求体 JSON 按 Student 校验——**坏数据（age="abc"、score=150）自动返回 422**，你一行 try/except 都不用写。
- **为什么今天用**：Day 14 你手动写 `safe_score` 做逐条容错，今天换成 FastAPI 自动挡——同样是 Pydantic，一个是手动调，一个是框架替你调。
- **怎么用**：路由函数参数的类型注解就是校验规则；`student.model_dump()` 把模型转回 dict（Pydantic v2 写法，`.dict()` 是 v1 旧版）。
- **坑**：422 的响应体是 `{"detail": [...]}`，每条错误含 `loc`（哪个字段）、`msg`（人话）、`type`（错误类别）——和 Day 14 你打印过的 `e.errors()[0]` 结构一样，只是被 FastAPI 包装成了 HTTP 响应。

### 5. 查询参数 vs 路径参数：数据放哪

- **是什么**：**路径参数**嵌在 URL 里（`/students/张三`），**查询参数**跟在 `?` 后面（`/students?min_score=70`）。路径参数是「你要找谁」，查询参数是「你要怎么过滤/排序」。
- **为什么今天用**：FastAPI 路由签名里 `{name}` 占位符 = 路径参数，`Query(0, ge=0, le=100)` = 查询参数带默认值和范围约束。今天两个 GET 各用一个，正好对比。
- **怎么用**：
  ```python
  @app.get("/students/{name}")                     # 路径参数：/students/张三
  def get_student(name: str): ...
  @app.get("/students")                            # 查询参数：/students?min_score=70
  def list_students(min_score: float = Query(0, ge=0, le=100)): ...
  ```
- **坑**（表述修正）：`/students/{name}` 只匹配「`/students/` + 一段非空内容」，**不会**吞掉 `/students`——`/students` 没有尾段，路径参数匹配不到；查询参数也不参与路由匹配。真正要小心的是固定子路径撞车：如果以后加 `GET /students/stats`，必须声明在 `{name}` 路由**前面**，否则 `/students/stats` 会被 `{name}` 当成名字截胡。查询参数校验失败（`?min_score=abc`）同样是 422。
