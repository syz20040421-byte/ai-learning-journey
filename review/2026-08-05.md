## 关键问题（明天追问，今天先记录）

### ① first_unique 用了 `collections.Counter` —— 把练习外包了

任务要求是「**用 dict 数一遍**」，练的是手写计数。`dict(Counter(items))` 把计数逻辑整个外包给了标准库——Counter 内部帮你做了 `count`。今天这个练习的核心就是「自己写那个循环」，外包了就白练了。

- 判罚：**重写一遍**，用普通 dict + `d[k] = d.get(k, 0) + 1` 手写计数，不要 import Counter
- 不算抄袭（Counter 是本进度内能理解的工具），但属于「绕开练习核心」

### ② notes 问题 3 答「O(1)」—— 大 O 概念没通

函数是：Counter 扫一遍 O(n) → 再遍历 result O(n) → 总体 **O(n)**，不是 O(1)。
「dict 查找是 O(1)」说的是**单次按键取值**；整个函数的复杂度要看**循环了几次完整遍历**。明天周检会拿这个追问。

### ③ `== None` 又出现了

昨天批改点名过 `assert(...) == None` 应写 `is None`，今天 `assert first_unique(["a","a","a"]) == None` 还是 `== None`。小事，但连续两天同一处。

### ④ merge_stock 缺「入参未变」assert

任务明确要求第 4 个 assert 验证调用后 a、b 内容没变。你的实现确实没改（`dict(a)` 拷贝了），但**验证没写**——验收标准差一条。

## 代码质量（不扣分，只提示）

- `first_unique_fast.py` 缩进用了 2 空格（Python 惯例 4 空格），跑得通但风格不标准
- `merge_stock.py` 里 `result[k] = b[k]` 写成 `result[k] = v` 更直接（遍历的 `k,v` 里 v 就是 b[k]）
- 中文注释「#有唯一元素」建议写成「# 有唯一元素」（空格），小习惯

## 结论

**功能达标、两处验收不达标**（缺入参 assert + 问题 3 答错）+ 一处重写（Counter → 手写 dict）。今天不算全过，明天批改前补齐：重写 first_unique、补第 4 个 assert、改 `is None`。三处都做完再 push 一个 commit。
